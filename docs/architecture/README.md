# docs/architecture

このディレクトリには、ユーザーが作成する設計書・仕様書を配置します。

## 重要ルール

- このディレクトリ配下のMarkdownは、ユーザー作成の学習成果物として扱います。
- AIは原則レビュー・助言を担当し、ユーザーの明示指示がある場合は設計書Markdownを編集・新規作成できます。
- 継続許可として、単体テスト着手前の不足仕様の追記と、ユーザー提示結果の記録を行います。未確定の期待動作は推測せず確認します。

## 想定する設計書

- `タスク管理機能/基本設計/`：要件定義・基本設計・DB・API・画面・認証認可等
- `タスク管理機能/詳細設計/`：構成・Entity・DTO・Repository・Service・Controller等
- `タスク管理機能/詳細設計/単体テスト仕様書.md`：単体テストケース・実施結果の正本
- `タスク管理機能/画面設計/ワイヤーフレーム.html`：画面構成案

Javaの配置方針はバックエンド構成設計書、最新の実装状況はdocs/context/current_tasks.mdを参照します。構成案と実装済み状態を区別してください。
